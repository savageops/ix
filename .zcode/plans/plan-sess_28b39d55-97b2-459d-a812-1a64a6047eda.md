Investigating the 50x performance gap between IX and ripgrep. The key finding from pass-011: IX takes ~3000ms vs ripgrep's ~59ms on the 6.6GB Linux benchsuite corpus.

Initial investigation reveals:
1. The binary was built in **Debug mode** (no -Doptimize flag = Debug default) — 2.9MB binary with bounds checking and zero optimizations
2. **thread_limit=2** — the 5% device cap limits threads to 2 on this machine, vs ripgrep using all cores
3. **trigram_acceleration.eligible=false** — the admission gate is not firing for `lit:EXPORT_SYMBOL`
4. **postings_index=not_wired** — no warm index, full scan of 1.34GB
5. **scan_file_buffered_ms_total** — using buffered reads, not mmap

The remediation plan:
1. Build with -Doptimize=ReleaseFast (Debug mode is the #1 suspect for the 50x gap)
2. Test with higher thread limits (the 5% cap is too aggressive for search)
3. Investigate why trigram admission is not eligible
4. Test with mmap enabled
5. Run a fair benchmark: same optimization, same threads, same corpus
6. Create a remediation QC pass with the findings
