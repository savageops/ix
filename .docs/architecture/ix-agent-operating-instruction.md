## Filesystem ownership

- `~/.ix/` is the sole mutable state root on every platform. Index generations, query/evidence caches, process markers, and future real `config.json` and `auth.json` contracts belong here. `IX_STATE_DIR` may replace the root for isolated tests and operator-controlled sandboxes; it never creates a second default.
- On Windows, `~/AppData/ix/ix.exe` is the sole live executable and `~/AppData/ix/backups/` owns predecessors. The executable directory contains no index, credentials, configuration, or runtime cache.
- Promotion verifies the candidate before mutation, stages it beside the destination, rotates the previous executable into backups, verifies the installed hash and warm/cold output contract, migrates the persistent user `PATH`, and preserves conflicting legacy state whole instead of merging generation trees.
- Configuration and authentication files are not manufactured before a consumer exists. When those capabilities land, their typed owners must read `~/.ix/config.json` and `~/.ix/auth.json`; until then the names are reserved architecture, not pretend functionality.
