# Goal 001 — Perpetual Perf Iteration and Search-Admission Discipline

This goal is a perpetual iteration contract: it never terminates, it only secures rounds. Each round optimizes the search engine's warm AND cold lanes against the live predecessor, demands 5% median improvement across the board in real scenarios, secures the win by commit to `develop-subzero`, promotes to current/installed, and then the winner becomes the predecessor for the next round — the bar moves forward, the catalog advances, iteration resumes. The inaugural predecessor anchor is the June 13 snapshot (`2026-06-13T21-14-53-726Z`). Three pillars hold the contract up, and they are inseparable: a benchmark-trust gate that refuses to take any win measured on a dirty host; a broad-spectrum kernel-and-admission hammer that pulls every failed tree and plants a strictly more powerful successor in the same hole; and a false-negative floor that treats correctness as outranking speed every time. A tricky perf exploit that lands as a +3% delta on a noisy host is indistinguishable from the 6.74% identity drift the 2026-07-04 smoke run manufactured, and a benchmark owner that can flip the sign of a 5.76% miss into a 5.07% win by swapping thread counts cannot be used to validate a Sheng table-in-register DFA or a search-admission policy that skips files. The hammer is the point of this goal; trust and correctness are the floor the hammer strikes against. Where prior rounds pulled a tree that did not take — exhausted specialist literal-alternates variants, scalar medium-literal bit-parallel paths, offset-only guards, broad-C-FFI shapes — this goal plants a strictly more powerful successor in each hole and demands it be measured on a clean host before any promotion, never re-planting an exhausted shape in any of its known forms. And where a kernel trick could be paired with a smarter admission policy that skips the file entirely, the admission lever is equal in priority — the fastest search engine is fastest because it knows what to ignore — but every admission decision carries a false-negative proof or it fails closed.

The trigger was a survey that catalogued dozens of underexploited tricks across SWAR, SIMD, bit-parallel algorithms, cache/TLB games, μop fusion, and I/O bypass — most of them already vendored in `.refs/` and none of them absorbed into IX's hot path — plus a parallel record (`.docs/log.md`) proving that the literal-alternates specialist lane has been hammered seven ways and did not retain. The lesson the survey draws is not "give up" — it is "broaden the spectrum and plant a strictly more powerful successor in each pulled hole." Where scalar medium-literal bit-parallel failed across three exploratory rounds, plant the Bit-(Parallelism)² AVX2-vectorized Glushkov NFA (Cantone–Faro–Giaquinta FUN 2010) that gives 4× the parallelism on the same algorithmic core by transposing the Bitap `B[]` table across four 64-bit SIMD lanes. Where exhausted literal-alternates variants did not retain against the June 30 predecessor, plant the Sheng table-in-register DFA (Langdale, branchfree.org) that handles the regex verification path at one PSHUFB per byte with zero memory traffic, and plant Rose-lite literal-chain dispatch so `foo.*bar` stops falling through to PCRE2. Where the broad-C-FFI shape was rejected, plant pure-Zig `@Vector` kernels that inline across the FFI seam. The broader spectrum does not stop there: the SWAR XOR-then-mask idiom for sub-32-byte tails; the lazy proof-positive `@reduce(.Max, chunk == target)` that dismisses a zero-match 32-byte chunk in ~1 cycle; the `VPCOMPRESSB` AVX-512 dense-pack that replaces the entire `while (mask) { @ctz; ...; mask &= mask-1; }` extraction loop with one instruction (Lemire: 8.5 vs 2.0 GB/s); the memchr2/memchr3 RotVec for worst-case-safe structural anchoring; the BWT r-index (Gagie–Navarro–Prezza SODA 2018, Move-r SEA 2024) that indexes source code in O(r) space where r ≪ n because source is the textbook high-repetition corpus. StringZilla ships a rarity-pivoted 3-byte fingerprint (`sz_locate_needle_anomalies_`) and a dormant AVX-512 skylake path; IX's `simd.zig` still uses a 2-byte first+last fingerprint and a single `-mavx2` flag. PCRE2 exposes `pcre2_jit_match_8`, the entry that "bypasses all sanity checks"; IX calls `pcre2_match_8` on every line even after JIT-compiling. BurntSushi/aho-corasick ships a 256-entry empirical byte-frequency table and a rare-byte memchr prefilter; IX picks trigrams positionally. The Hyperscan snapshot carries the `TEDDY_VBMI_PSHUFB_OR_*` macros that document the 2×PSHUFB Shufti idiom applicable far beyond multi-literal matching; IX routes byte-class queries through a per-call FFI. The untried tricks are already in the repo. The hammer's job is to admit, port, and measure the whole spectrum under a fixed resource profile — IX adapts to whatever resources are available (the realistic case: Codex, Chrome, and the rest of the user's workload are running, the host is never clean), and the level playing field comes from pinning the resource ceiling (`resource_profile=low`: min cores, min memory) so the result is consistent and comparable regardless of host noise.

The first trick family is SWAR and the byte-per-cycle SIMD primitives. SWAR (SIMD-Within-A-Register) packs 8 bytes into a u64 and finds candidates with the classic `((x ^ broadcast) - 0x01010101) & ~x & 0x80808080` zero-byte-detection trick — this is what glibc's `strlen` and `memchr` use, what StringZilla's `sz_find_serial` falls back to when AVX is off, and what IX's `simd.zig` has no tier for. Above SWAR sits the `VPCMPEQB + VPMOVMSKB + TZCNT` idiom — broadcast a byte into a YMM, compare 32 lanes, extract a 32-bit mask, count trailing zeros — which IX already uses for `indexOfByte` but does not exploit for multi-byte classification, structural anchoring, or proof-positive dismissal. The hacky behaviors here are: the XOR-then-mask SWAR trick for the <32-byte tail instead of a scalar loop; the `@reduce(.Max, chunk == target)` lazy proof-positive that dismisses a zero-match 32-byte chunk in ~1 cycle before the TZCNT extraction loop even runs; and the `VPCOMPRESSB` (AVX-512 VBMI2) dense-pack that gathers matching byte positions into an output register in one instruction, replacing the entire `while (mask) { bit = @ctz(mask); ...; mask &= mask-1; }` loop. Lemire clocks the compress-store at 8.5 GB/s vs 2.0 GB/s on SSE4.2; the question is whether IX's AVX2-only build can justify a second compile target for it.

The second trick family is the PSHUFB idiom — using `vpshufb` as a 16-entry lookup table that classifies 16 bytes in one op. Langdale's "SMH: The Swiss Army Chainsaw of Shuffle-Based Matching Sequences" documents the family: Shufti (two 16-byte tables, lo nibble and hi nibble, AND-combined → arbitrary byte-set membership in 3 ops), Sheng (the entire DFA transition table lives in SIMD registers, one PSHUFB per byte, ~1 cycle/byte for ≤16-state automata — Langdale calls it "the fastest DFA per cycle"), and the Hyperscan `truffle`/`vermicelli` specializations. The hacky behavior is treating PSHUFB as a vectorized LUT: each lane loads `table[byte]`, so one shuffle classifies 16 (or 32) bytes against a 256-entry alphabet compressed into two 16-entry half-byte tables. IX has no Shufti primitive; every character-class query pays FFI to `sz_find_byteset`. A pure-Zig `@Vector(16, u8)` Shufti with `@shuffle` lowering to `vpshufb` is ~100 LOC and inlines into any caller. This is the highest ratio of value to effort in the entire catalog.

The third trick family is bit-parallel string matching — one bit per automaton state, one `&`/`|`/`<<` per text byte. The lineage is Baeza-Yates–Gonnet 1992 (Shift-Or/Shift-And/Bitap), Wu–Manber 1992 (agrep fuzzy extension, `k+1` state words covering substitution/insertion/deletion in O(n·k)), Myers 1999 (the bit-vector edit-distance algorithm at O(n·⌈m/w⌉), distinct from and faster than Wu-Manber for large m), Navarro–Raffinot 2000 (BNDM — Backward Nondeterministic DAWG Matching, right-to-left windowed, average sublinear), and the Glushkov ε-free NFA construction that lets any regex with ≤64 states simulate in O(n) with one word of state. Navarro–Raffinot's *Flexible Pattern Matching in Strings* (Cambridge 2002) is the canonical reference. **The scalar form of this family was tried in the medium-literal bit-parallel exploratory pass (`.docs/research/2026-07-04-medium-literal-bitparallel-exploratory.md`) across three rounds and never left `exploratory` grade on a noisy host — so this goal pulls the scalar tree and plants the Bit-(Parallelism)² AVX2-vectorized Glushkov NFA in the same hole (Cantone–Faro–Giaquinta FUN 2010): the per-byte step `D = ((D << 1) | 1) & B[c]` becomes a vector op testing four text positions per AVX2 cycle, four times the parallelism of the failed scalar form on the same algorithmic core, with the Glushkov ε-free construction eliminating the epsilon-closure pass that prevents naive Thompson NFAs from vectorizing cleanly.** IX's regex path falls back to PCRE2-JIT for every regex query; for the ≤64-state majority, a Zig bit-(parallelism)² Glushkov-NFA matcher would beat it without JIT warmup, without the C dependency, and without the per-line sanity-check overhead the JIT-bypass entry was designed to skip.

The fourth trick family is the "Bit-(Parallelism)²" construction — vectorizing bit-parallel matching across SIMD lanes. Cantone–Faro–Giaquinta (FUN 2010) observed that bit-parallel uses a w-bit scalar word while SIMD gives a W-bit register = W/w independent lanes; running W/w independent bit-parallel matchers (one per SIMD lane, each tracking a different text window or pattern) multiplies the parallelism. On AVX2 that's 4× (four 64-bit lanes); on AVX-512, 8×. Van Engelen/Genivia shows the concrete recipe: transpose the Bitap `B[]` table so each SIMD lane holds one column, then `D = (D<<1) | B[c]` becomes a vector op testing 4 (or 8) text bytes at once. Sneller's production regex engine uses this for ~1.5 GB/s/core. This is the one place IX could plausibly exceed re2/Hyperscan-class regex throughput on small regexes — and it composes directly with the Glushkov NFA above.

The fifth trick family is the Hyperscan engine decomposition — the production reference for high-throughput matching, and a portfolio in itself rather than a single engine. Wang et al. NSDI 2019 documents the pipeline: Rose (literal-anchored dispatch graph — extract required literals from each regex, run multi-literal scan, only invoke the verifier near literal hits), Limex (bit-parallel Glushkov NFA with shuffle-based step function + "accel" that skips to the next byte that could wake a sleeping state — 1-3 cycles/byte when accelerated), Sheng (table-in-register DFA, ≤16 states, one PSHUFB/byte), McClellan (larger SIMD-DFA with equivalence-class grouping), and the FDR bucketed shift-or literal layer (100+ Gbps/core). The hacky behavior is two-stage prefilter-then-verify: the cheap SIMD layer dismisses >95% of bytes, the expensive NFA/DFA runs only on candidate windows. The discipline this goal demands is breadth: harvest the full engine portfolio from the Vectorscan fork (`github.com/VectorCamp/vectorscan`, the maintained portable reference), not just one engine. IX's trigram admission gate is a degenerate one-literal Rose; the survey's Rose-lite proposal (~500 LOC) would handle `foo.*bar` as "find foo, then bar within window, only then run regex" — a genuinely new capability IX does not have, not a re-skinning of an exhausted lane.

The sixth trick family is literal-anchored dispatch and verification — the broad-spectrum layer behind the prefilter, none of which IX has admitted. The Sheng table-in-register DFA (Langdale, branchfree.org/2018/05/25/say-hello-to-my-little-friend) takes any regex whose minimized DFA has ≤16 states and runs the entire transition table inside SIMD registers — the per-byte step is one `vpshufb` with the current state's mask indexed by the input byte, zero memory traffic per transition, ~1 cycle/byte, no JIT, no PCRE2 fallback. The McClellan larger SIMD-DFA (Hyperscan NSDI 2019 §5.1) extends the same idea with equivalence-class grouping for automata that do not fit Sheng's 16-state budget. Rose-lite literal-chain dispatch (Hyperscan NSDI 2019 §4) extracts the ordered required literals from each regex, runs multi-literal scan over all of them, checks pairwise "A before B, distance ≤ window" with a simple offset comparison, and only invokes the verifier on chain survivors — ~500 LOC, handles `foo.*bar` as a sequence of literal hits rather than falling through to PCRE2. The Limex bit-parallel NFA with "accel" (Wang et al. NSDI 2019 §5.2) handles the medium-state-count regex band that neither Sheng nor McClellan owns, skipping forward to the next byte that could wake a sleeping state at 1-3 cycles/byte when accelerated. The memchr2/memchr3 RotVec technique (BurntSushi/memchr) handles unaligned overlap reads without a slow tail. The rare-byte selection heuristic (BurntSushi's `byte_frequencies.rs` 256-entry table) picks the rarest byte in each pattern as the memchr anchor, so `function` scans for `f` not `n`. The hacky behavior is treating the literal-anchored layer as a Sheng-or-McClellan verifier behind a Rose-chain prefilter, with the rare-byte heuristic choosing the literal that dismisses the most input per cycle — a portfolio of complementary engines, not a single hammered specialist. The exhausted literal-alternates variants belong to a different (already-explored) family and are not on this goal's hammer list; their successors in the dispatch-and-verification layer are the Sheng/McClellan/Rose/Limex names above.

The seventh trick family is cache, TLB, and store-buffer games. Huge pages (`MAP_HUGETLB` on Linux, `MEM_LARGE_PAGES` + `SeLockMemoryPrivilege` on Windows) collapse 512 × 4 KiB TLB entries into one 2 MiB entry — FoundationDB measured +14% on GET throughput, Factorio measured >20% UPS on a multi-GB pointer-heavy workload. `@alignCast(32, ...)` on stack buffers guarantees store-to-load forwarding success (a misaligned 32-byte SIMD load crossing a 32-byte boundary stalls ~12 cycles). Non-temporal stores (`_mm256_stream_si256` / `@prefetch` with `.cache = .none`) prevent `SearchHit` result writes from evicting hot scan data from L1/L2. The lazy proof-positive two-pass scan (`@reduce(.Max, chunk == target)` to dismiss a zero-match chunk in ~1 cycle, second pass only on positives) is the columnar-scan philosophy adapted for text. Software prefetch (`prefetcht0` vs `prefetchnta`) — frontier guidance is "don't bother for sequential scan" (Algorithmica, Travis Downs, TU Dortmund 2024) but DO add `@prefetch` ~6 lines ahead in index-probe loops, where the address is predictable-but-far and the HW prefetcher can't infer it. The hacky behavior is treating the cache hierarchy as an explicit memory pyramid, not an assumption.

The eighth trick family is μop fusion, branch discipline, and code-layout games. Guaranteeing `TEST`/`JNZ` fusion in the decoder by preventing flag-clobbering instructions between compare and branch — Zig's `@Vector` + `@reduce` path gets this for free if structured correctly. `@setCold()` / `@branchHint(.cold)` to push recoverable-error and scalar-tail paths out of L1i (Hyperscan's `accel` does this implicitly). Branchless CMOV patterns for max/min/selection where the branch predictor would mispredict. Profile-guided optimization (PGO) — `-fprofile-generate`/`-fprofile-use` — to bake real branch frequencies into the layout. LTO across the Zig/C boundary (`want_lto = .full` on the C source steps) so LLVM sees the whole TU graph and inlines StringZilla's hot compare loops across the FFI seam — AGENTS.md Tier 3 lists this; `build.zig` never sets it. The hacky behavior is treating the decoder and branch predictor as adversarial inputs to be appeased, not ignored.

The ninth trick family is set-intersection and posting-list tricks. The Demaine–López-Ortiz–Munro adaptive bound (SODA 2000) — galloping (exponential-then-binary) search when set-size ratios exceed ~8:1, achieving O(|small| · log(|large|/|small|)) instead of O(|a|+|b|); this is the algorithm inside TimSort's merge and Roaring's array-array kernel. Roaring bitmaps' adaptive container dispatch (array ≤4096, bitset >4096, run for consecutive) — array∩bitset is O(|array|) bit-tests, a ~1000× algorithmic win on rare-vs-common trigram pairs. Elias-Fano quasi-succinct encoding (~2 bits/element beyond information-theoretic minimum, O(1) select). SIMD intersection (Inoue VLDB 2015 galloping-SIMD, FESIA ICDE 2020 segmented bitmaps, SimSIMD up to 5× on AVX-512/SVE2). The r-index over BWT runs (Gagie–Navarro–Prezza SODA 2018, Move-r SEA 2024) for repetitive corpora — source code is exactly the textbook use case. IX's `intersectFileIds` is a textbook two-pointer merge with no adaptive dispatch; the galloping win is ~20 LOC and composes with every later container representation.

The tenth trick family is I/O and syscall tricks — relevant when scan-per-byte becomes memory-bound. io_uring SQPOLL + `IORING_OP_READ_FIXED` with pre-registered page-aligned buffers (TigerBeetle `src/io/linux.zig` is the Zig reference) — zero submission syscalls under sustained load. The "magic ring buffer" double-map (Ryg 2012; same physical pages mapped twice contiguously) for boundary-free SIMD scan with no carry tail. IOCP with `FILE_FLAG_NO_BUFFERING` on Windows for sector-aligned direct reads. The `madvise(MADV_HUGEPAGE)` / `MADV_SEQUENTIAL` / `MADV_WILLNEED` hints. The single-syscall-per-small-file pattern (`readPositional` first, defer `file.length()` until chunk overflows) — IX already does this. Mmap-vs-read policy: ripgrep defaults `MmapChoice::Never` for directory search because mapping-management overhead exceeds read cost on many small files; IX's `scan_input_policy.zig` now exposes the knob. The hacky behavior is owning the I/O path explicitly rather than trusting the kernel's LRU.

The eleventh trick family is profiling and measurement at the PMU level. `perf_event_open` to read `CACHE_MISSES`, `BRANCH_MISSES`, `INSTRUCTIONS`, `CPU_CYCLES` per benchmark run; `rdpmc` for cycle-accurate reads without kernel transition (the gotta-go-fast reference). Agner Fog's instruction tables and optimization manuals for per-μarch throughput/latency. The AMD Zen 4 Software Optimization Guide and Intel Optimization Reference Manual for the official prefetch/fusion/port guidance. Brendan Gregg's utilization and noise methodology. The Microsoft Defender Performance Analyzer (`New-MpPerformanceRecording`/`Get-MpPerformanceReport`) for proving the host is clean. pyperf system-tuning for the Linux equivalent. The arXiv:2411.08494 "Achieving Consistent and Comparable CPU Evaluation Outcomes" discipline. The hacky behavior is treating measurement as an adversarial inference problem: the host wants to fool you, the scheduler wants to fool you, Defender wants to fool you — only PMU counters and a certified-clean envelope tell the truth.

The validation contract for every round under this goal is the full pyramid, and the benchmark-trust gate is the final, decisive layer. `node --check` on every changed script; `node tools/scripts/lib/schema-self-test-gate.mjs` for the report schema; `zig build test --summary all` for the engine (441/443 with 2 skipped is the current floor); `zig build -Doptimize=ReleaseFast --summary all` for the optimized build; `ix-zig.exe process status --json` confirming `live=0 stale=0 malformed=0 warnings=0 removed=0`; and, before any speed claim, the architecture speed-only gate with `planning_queue=ok`, `diff_check=ok`, `process_scan=ok`, and `benchmark_host_preflight=ok`. The 2026-07-04 falsification — 12-sample −5.76%, 16-thread identity drift 6.74%, 32-thread +5.07% — proved the host can manufacture any verdict. AGENTS.md now codifies Benchmark Falsification Before Runtime Blame: prove match parity, route parity, binary provenance, same-binary identity drift under 3%, host preflight clean, scheduler isolation, Defender interference absent, and phase-timing exclusivity before attributing loss to a search kernel. The single-hardest-valid-predecessor discipline forbids the older-snapshot ladder as a promotion requirement — a multi-backup ladder manufactures a friendly predecessor whenever one is needed. A miss smaller than observed identity drift is exploratory, not a verdict. A route-local win with a small whole-engine loss is a salvage problem, not a revert command.

What this goal explicitly forbids is the lazy move in both directions. It forbids reverting or rejecting a runtime candidate from a round whose identity drift exceeds its delta, whose host preflight failed, or whose match parity is broken. It forbids taking a tricky-perf-exploit win measured on a dirty host as retained proof. It forbids opening a round without the Insect and `.refs/` harvests named above. It forbids reintroducing the older-snapshot ladder as a promotion requirement. It forbids re-planting any exhausted shape from the literal-alternates specialist lane (the seven documented variants and their offset-only / scalar-guard / broad-C-FFI wrappers are all spent) — the only acceptable moves in those holes are the broad-spectrum successors named in this goal (Bit-(Parallelism)² Glushkov NFA, Sheng table-in-register DFA, McClellan SIMD-DFA, Rose-lite dispatch, Limex accel, pure-Zig `@Vector` kernels, the r-index over BWT runs). It forbids treating a single trick — whether an exhausted one or a fresh one — as the whole answer when the survey established a broad portfolio plus a warm/index layer of rarest-first n-gram planning, density-aware postings, and adaptive galloping intersection. And it forbids collapsing the catalog onto any one lane while leaving the rest of the spectrum unexploited. The chains `001-hot-path-perf` (invariant alignment — LTO, alignment, cold-paths, simd routing, RotVec anchoring) and `002-frontier-absorption` (3-byte rarity-pivoted fingerprint, PCRE2 JIT bypass, galloping intersection, pure-Zig Shufti) lock in the first absorptions across the spectrum; this goal is the umbrella that demands the rest of the spectrum — Sheng, McClellan, Rose-lite, Limex, the Bit-(Parallelism)² Glushkov NFA, the AVX-512 build, Roaring, the r-index, huge pages, io_uring — be hammered next under a trustworthy envelope.

The perpetual iteration contract is the engine of this goal, and it never terminates. A round closes only when five conditions hold simultaneously: the warm lane AND the cold lane are both measured against the live predecessor under a FIXED resource profile (`resource_profile=low`: min cores, min memory — so the result is consistent and comparable regardless of host noise; the realistic case is that Codex, Chrome, and the user's real workload are running, and IX adapts down rather than demanding the host be clean); the median improvement across real scenarios (not synthetic, not a single needle, not exploratory grade) is at least 5% across the board; match parity is proven so no false negative was introduced by admission or kernel changes; the win is secured by a commit to `develop-subzero`; and the secured binary is promoted to current/installed. The instant those five hold, the winner becomes the predecessor for the next round — the bar moves forward, the catalog advances, and iteration resumes. The June 13 snapshot (`2026-06-13T21-14-53-726Z`) is the inaugural predecessor anchor; every subsequent promotion replaces it. The bench dashboard's UI is the conceptual reminder: lanes for warm, cold, installed, hardest-predecessor, identity drift, and match parity, all visible at once, all required green before a round closes. The search-admission discipline is the second axis of optimization and it is equal in priority to the kernel tricks. The fastest search engine is fastest because it knows what to search for and what to ignore — but the floor on every admission decision is false-negative safety. A prefilter that skips a file containing a true match has not optimized; it has lied. The admission levers are: rarest-first trigram and n-gram planning (Russ Cox's "Regular Expression Matching with a Trigram Index," Zoekt's posting intersection, Tantivy's skipped-block inverted index) so the rarest evidence is intersected first and the common trigrams never run; file-type and sheen admission so binary blobs, generated artifacts, vendored dependencies, and `node_modules`-class subtrees are dismissed before I/O; directory-walk pruning via ignore-rule compilation (ripgrep's `WalkParallel` + `gitignore` semantics) so uninteresting subtrees never enter the file list; content-sniff binary dismissal on the first chunk so a mis-admitted binary is rejected after one read not after a full scan; mtime and size heuristics for warm-layer invalidation so unchanged files are not re-scanned; and density-aware postings representation (Roaring array/bitset/run containers, Elias-Fano quasi-succinct) so the admission intersection itself runs at the Demaine adaptive bound. Every one of these levers MUST be paired with a false-negative proof — a corpus-walk verifier that confirms the optimizer's answer set equals the brute-force answer set on adversarial fixtures (binary files renamed to `.txt`, source files with `\0` injected, deeply-nested unignored paths, near-trigram-threshold patterns, case-folding edge cases, regex with zero-width matches). If a faster admission path cannot prove parity against brute force, it fails closed (search the file anyway) rather than fail open (silently skip). The `matchParity === false` gate already blocks timing attribution by construction; under this goal it also blocks promotion by construction. A round that ships a 5% median win but introduces a single false negative has not closed — it has regressed on correctness, and correctness outranks speed every time.
